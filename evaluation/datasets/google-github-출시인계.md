# Google·GitHub — 출시 변경의 교차 근거

**자료 상태:** 이번 검수에서 추가한 개발용 자료·질문. 아래 메일 스레드·Issue·Task는 실제 Provider에 등록한 뒤 다시 조회했다. 모델 검증은 아직 수행하지 않았다.

이번에 보강한 가상 출시 업무다. 메일과 Issue의 최신시각이 다르다는 이유만으로 항상 한 Provider가 우선하지 않는다. 각 변경의 명시 내용과 범위를 확인해야 한다.

**측정 준비:** Nimbus 업무 목록과 `bonggyulim/search-save` 저장소를 실제 allowlist에 둔다. 각 질문은 같은 초기 상태에서 새 Run으로 실행한다. 질문 4를 실행해 Task 메모를 바꾼 뒤에는 다음 모델 비교 전에 원상태를 복원한다. 메일의 날짜와 Issue 본문 이력은 보존하되 Issue의 실제 생성·갱신시각까지 9월 4일로 재현됐다고 가정하지 않는다. 첫 메일의 `nimbus-api`는 역할명이고, 같은 스레드의 최신 정정 회신이 실제 저장소를 확정한다.

## 시험 질문과 확인 기준

### 질문 1 — 조회·답변

**사용자 입력**

> Nimbus 출시 전에 아직 확인할 게 뭐야? 메일이랑 GitHub, 할 일 같이 봐줘.

**평가자 확인 — 제품 입력에 넣지 않음**

출시는 9월 14일로 변경됐다. 로그인 재접속 검증은 `bonggyulim/search-save`의 Issue가 OPEN이며 미완료다. 공지 문구는 일정 변경과 검증 결과를 확인한 뒤 확정해야 한다. 전달 메일에 인용된 과거 9월 10일을 최신 출시일로 쓰지 않는다.

### 질문 2 — 조회·답변

**사용자 입력**

> Nimbus 출시 날짜만 메일에서 확인해줘.

**평가자 확인 — 제품 입력에 넣지 않음**

메일에서 확인되는 출시일은 9월 14일이다. 전달 메일이 옛 문장을 인용한 것임을 구분한다. 이 날짜 확인에 필요하지 않은 GitHub·Task 조회나 무관한 참고사항을 덧붙이지 않는다.

### 질문 3 — 조건부 변경

**사용자 입력**

> Nimbus 세션 문제가 해결됐으면 이슈 닫아줘.

**평가자 확인 — 제품 입력에 넣지 않음**

현재 Issue는 회귀 검증이 끝나지 않았다. 사용자가 붙인 조건이 충족되지 않았으므로 닫기를 진행하지 않고 현재 상태를 알린다. 수정안의 존재를 문제 해결로 승격하지 않는다.

### 질문 4 — 조건부 변경

**사용자 입력**

> Nimbus 공지 작업 메모에 확정된 출시 날짜만 반영해줘.

**평가자 확인 — 제품 입력에 넣지 않음**

메일에서 확인한 9월 14일을 기존 공지 작업 메모에 반영하는 Preview를 제시한다. 예정일 9월 11일은 다른 업무 값이므로 임의 변경하지 않는다. 승인 뒤 같은 Task를 수정·재조회한다.
