# Quartz — 납품 확인 회신

Draft와 실제 답장 전송을 구분하고 원래 스레드를 유지한다.

**보강 자료:** 임시보관 Draft와 질문 2·3은 이번 재검수에서 추가한 가상 초기 자료·시험이다. 원본의 과거 실행 결과로 소급 사용하지 않는다.

**실제 등록 전:** [실행 안내](../README.md)의 계정·날짜·권한 준비를 따른다. 메일·초대 주소는 이 문서에 적힌 승인된 세 계정 안에서만 사용한다. 이름·부서는 가상 업무 역할이며 실제 계정 소유자의 신원이 아니다. 날짜를 옮겨야 하면 자료·질문·확인 기준을 함께 옮기고 실행 기록에 적는다. 본문에 없는 연도·소요시간·승인 사실을 채워 넣지 않는다.

## 시험 질문과 확인 기준

승인 전 계획 확인과 실제 외부 변경 완료는 별도 판정이다. 공통 기준은 [실행과 판정](../README.md#실행과-판정)을 따른다.

### 질문 1 — CASE-CORE-059 · 계획·승인 전 확인

**사용자 입력**

> Quartz 납품 일정 확인했다고 답장 보내줘.

**같은 뜻의 다른 말투** — 각각 새 Run으로 실행한다.

한국어:
> Quartz 납품 일정 확인했다는 답장 보내줘.

English:
> Send a reply confirming that I have checked the Quartz delivery schedule.

**평가자 확인 — 제품 입력에 넣지 않음**

실제 Quartz 스레드의 납품일 8월 21일을 근거로 확인 답장을 제안한다. 전송 요청을 Draft로 축소하지 않으며 승인 뒤 새 sent reply와 thread 관계를 재조회한다.

### 질문 2 — Draft 저장

**사용자 입력**

> Quartz 납품일 확인 메일을 새로 써서 jjssyy0527@gmail.com 앞으로 임시보관함에 저장해줘. 보내지는 말고.

**평가자 확인 — 제품 입력에 넣지 않음**

수신 메일에서 8월 21일 납품을 확인해 새 Draft의 내용을 준비한다. 사용자가 저장을 명시했으므로 본문만 출력한 결과를 저장 성공으로 보지 않는다. 승인 뒤 새 Draft가 실제로 존재하고 수신자·제목·본문을 재조회해 확인한다. 기존 「Quartz 납품 회신 검토」 Draft는 변경하지 않고 전송은 0이다.

### 질문 3 — 기존 Draft 수정

**시작 조건:** 질문 2로 생성한 Draft가 아니라 초기 자료의 「Quartz 납품 회신 검토」 Draft를 대상으로 한다. 제품이 Draft를 찾거나 선택할 수 있는 실제 경로를 확인한다. 수신 메일을 선택한 것을 Draft 선택으로 간주하지 않는다.

**사용자 입력**

> 임시보관함의 “Quartz 납품 회신 검토” 초안 끝에 “8월 21일 입고 준비를 확인 중입니다.”만 추가해줘. 보내지는 마.

**평가자 확인 — 제품 입력에 넣지 않음**

정확한 기존 Draft에 해당 문장을 한 번 추가한다. 수신자·기존 문장·제목·스레드 관계를 보존하며 새 Draft나 SEND로 대체하지 않는다. 승인·수정·독립 재조회까지 실제로 수행한 경우만 UPDATE 완료다. 현재 제품에서 이 경로가 없으면 구현 또는 연결 공백으로 기록하고 다른 동작 성공으로 대신하지 않는다.
