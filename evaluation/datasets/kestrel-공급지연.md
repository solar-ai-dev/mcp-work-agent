# Kestrel — 선적 지연과 후속 확인

지연 사실·현재 Task 상태·아직 모르는 납품일을 구분한다.

**실제 등록 전:** [실행 안내](../README.md)의 계정·날짜·권한 준비를 따른다. 메일·초대 주소는 이 문서에 적힌 승인된 세 계정 안에서만 사용한다. 이름·부서는 가상 업무 역할이며 실제 계정 소유자의 신원이 아니다. 날짜를 옮겨야 하면 자료·질문·확인 기준을 함께 옮기고 실행 기록에 적는다. 본문에 없는 연도·소요시간·승인 사실을 채워 넣지 않는다.

## 시험 질문과 확인 기준

승인 전 계획 확인과 실제 외부 변경 완료는 별도 판정이다. 공통 기준은 [실행과 판정](../README.md#실행과-판정)을 따른다.

### 질문 1 — CASE-CORE-009 · 조회·답변

**사용자 입력**

> Kestrel 지연 건 지금 어디까지 됐어? 메일이랑 할 일 같이 봐줘.

**평가자 확인 — 제품 입력에 넣지 않음**

메일의 선적 이틀 지연과 기존 「Kestrel 대체 일정 확인」 작업의 미완료 상태를 구분한다. 새로운 확정 납품일은 자료에 없다.

### 질문 2 — CASE-CORE-015 · 계획·승인 전 확인

**사용자 입력**

> Kestrel 대체 일정 확인 작업이랑 8월 8일 일정을 보고 qhdrbdhkdwks2@gmail.com에 확인할 메일을 Gmail 초안으로 저장해줘. 보내지는 마.

**평가자 확인 — 제품 입력에 넣지 않음**

대체 일정 확인 작업은 미완료, 예정일은 8월 8일이다. 실제 허용 캘린더의 조회 범위에서만 비어 있는 시간을 말한다. 소요시간·근무 여부가 없으면 하루 전체를 무조건 가능하다고 하지 않는다.

확인할 계획은 명시된 수신자와 업무 내용을 가진 Gmail Draft 저장이다. 본문 제안만으로 외부 저장 검증을 대신하지 않는다. 승인 전 저장·전송 0, 실행까지 시험하면 승인한 Draft 1개를 별도 재조회하며 SEND는 없다.

### 질문 3 — CASE-CORE-023 · 계획·승인 전 확인

**사용자 입력**

> Kestrel 지연 건 메일이랑 할 일 보고 8월 8일 오전 10시에 30분 점검 잡아줘.

**같은 뜻의 다른 말투** — 각각 새 Run으로 실행한다.

한국어:
> Kestrel 지연 메일하고 할 일 보고 8월 8일 오전 10시부터 30분 점검 잡아줘.

English:
> Check the Kestrel delay emails and task, then schedule a 30-minute check for August 8 at 10 a.m.

**평가자 확인 — 제품 입력에 넣지 않음**

8월 8일 10~10시 30분을 보존하고 지연 메일·기존 작업·실제 충돌 여부를 확인한다. 이 날짜는 토요일이므로 현재 근무 설정과 필요한 확인을 존중한다.

### 질문 4 — CASE-CORE-028 · 계획·승인 전 확인

**사용자 입력**

> Kestrel 지연 메일이랑 할 일 보고 8월 8일 업무시간 중 30분 비는 때에 점검 일정 잡아줘.

**평가자 확인 — 제품 입력에 넣지 않음**

8월 8일은 토요일이다. 주말 제외 설정이면 업무시간이 있다고 가정하지 않고 필요한 선택을 확인한다. 주말 사용을 허용한 조건에서는 실제 30분 가용 구간을 찾는다.

### 질문 5 — CASE-CORE-034 · 계획·승인 전 확인

**사용자 입력**

> Kestrel 지연 메일과 8월 첫째 주 일정을 보고, 8월 8일까지 공급업체에 다시 확인할 일 만들어줘.

**평가자 확인 — 제품 입력에 넣지 않음**

메일에서 지연 사실을 확인한다. 기존 대체 일정 확인과 공급업체 후속 확인이 같은 일인지 메모·목적을 대조하며 모호하면 확인한다. 제목 차이만으로 새 작업 생성을 정당화하지 않는다.

### 질문 6 — CASE-CORE-040 · 계획·승인 전 확인

**사용자 입력**

> Kestrel 지연 메일과 8월 첫째 주 캘린더 보고, 기존 대체 일정 확인 작업 메모에 선적이 이틀 늦는다고 추가해줘.

**평가자 확인 — 제품 입력에 넣지 않음**

기존 대체 일정 확인 Task의 메모에 메일이 확인한 선적 2일 지연을 추가한다. 다른 Task와 예정일을 바꾸지 않는다.

### 질문 7 — CASE-CORE-043 · 조회·답변

**사용자 입력**

> Kestrel 메일이랑 할 일, 8월 첫째 주 일정을 보고 지금 뭘 먼저 확인해야 할지 알려줘.

**평가자 확인 — 제품 입력에 넣지 않음**

선적이 이틀 늦어진 사실과 대체 일정 확인 Task가 미완료임을 연결한다. 새 납품일 확정 여부를 먼저 확인할 필요가 있으며, 빈 캘린더만으로 납품 가능을 증명하지 않는다.

### 질문 8 — CASE-CORE-048 · 계획·승인 전 확인

**사용자 입력**

> Kestrel 메일이랑 할 일, 캘린더 보고 기존 대체 일정 확인 메모에 이틀 지연을 추가해줘. 8월 8일 오전 10시에 30분 점검도 잡고, 두 작업이 처리된 뒤 jjssyy0527@gmail.com에 안내할 메일을 Gmail 초안으로 저장해줘. 보내지는 마.

**평가자 확인 — 제품 입력에 넣지 않음**

기존 Kestrel 대체 일정 확인 Task의 메모 UPDATE, 8월 8일 10~10시 30분 Event CREATE, jjssyy0527@gmail.com 수신 Draft CREATE를 구분한다. Draft는 앞선 두 결과가 확인된 뒤에만 저장한다. 기존 Task의 예정일·상태·미요청 메모를 보존하고 각 효과를 별도로 재조회한다. 선행 실패·결과 미확정 때 성공 안내를 저장하지 않는다. 토요일 근무·충돌 조건은 실제 설정으로 확인하며 SEND는 없다.
